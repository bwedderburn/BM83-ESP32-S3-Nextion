# v0.1.0 — BM83 Remote source preview

**Draft prerelease.** This is the proposed first GitHub release. It packages the
controller application source and documents the current project scope; it is not
an accepted native-runtime or complete-system firmware release. The final GitHub
draft must record the exact reviewed source revision and attached asset hashes.

## Project scope

BM83 Remote uses an ESP32-S3 controller to communicate with a Microchip BM83 audio
module and a Nextion touchscreen over UART. BM83 carries the Bluetooth audio;
the controller supplies transport commands, metadata handling and optional BLE
HID volume keys. The hardware setup includes UDA1334A and Adafruit PCM5100 I²S
DAC boards. Their presence does not imply that both outputs are used together or
that this release has qualified every DAC configuration.

The optional 7-inch CrowPanel remote provides Now Playing text, elapsed/total
time, a display-only progress bar, transport controls and Volume −/+ buttons.
Its Settings page exposes power, EQ, pairing and Wi-Fi/artwork setup. Artwork
uses a catalog lookup from track metadata; it is not BM83 UART cover-art transfer.
Available source metadata depends on the connected host and app.

Volume controls send relative BLE HID Consumer Control keys. **Absolute source
volume feedback and a synchronized absolute-volume slider are not available.**
Mute synchronization has not been pursued and is not a release feature. The
presence of a low-level HID MUTE command does not establish mute-state feedback.

## Included in the source preview

- Controller application source, with the early `boot.py`, `main.py`, project
  libraries and an inactive settings example.
- Current deployment, Nextion setup, BLE handoff, troubleshooting and validation
  documentation.
- Host tests, scan configuration and pinned build-tool recipes in the repository.
- Source for optional artwork/metadata helpers and the Universe badge add-on in
  the full repository; these are separate integrations with their own setup and
  acceptance limits.

Native CircuitPython flash images, CrowPanel flash images, Adafruit dependencies,
private enrollment profiles and device backups are not included in the proposed
application ZIP. Separately install compatible Adafruit BLE/HID libraries using
the deployment guide. Preserve their upstream licenses when distributing them.
Project-authored code uses the [MIT license](../../LICENSE). Complete repository
source archives also contain retained vendor references under their own terms;
the MIT license does not relicense that material.

## Installation and recovery

Start with [application deployment and rollback](../guides/deployment.md) and
[Nextion setup](../guides/nextion-setup.md). Use the source application mode for
initial bring-up, preserve existing private configuration, and keep application
updates distinct from runtime flashing. For an established installation, review
[BLE volume handoff](../guides/ble-volume-handoff.md) and
[bond-preserving runtime updates](../guides/ble-runtime-update.md) before changing
its host connections or runtime.

Do not blindly copy a complete repository or source archive onto a device. The
application ZIP is a source package, not an installer. Its settings example does
not contain live credentials and must not replace an existing private settings
file. Consult the CrowPanel [build/setup guide](../../firmware/crowpanel-remote/README.md)
for that separate board and the [Mac metadata bridge guide](../guides/mac-metadata-bridge.md)
for the optional host-assisted path.

## Evidence and known limits

Historical user checks established audible playback, transport/relative-volume
controls and metadata/timing on specific Windows, iPhone and Mac configurations.
These observations do not qualify all hosts or the current receiver-bearing
integration. [Dated validation records](../validation/) and the
[reliability runbook](../reliability/README.md) retain the exact scopes and gaps.
Host/CI tests and reproducible native builds do not replace physical acceptance.

Windows Apple Music has shown a silent, stalled source clock after BM83 power
cycling even while Nextion metadata and its predicted clock continue. A Windows
Bluetooth audio disconnect/reconnect restored the tested configuration; automatic
unit-only recovery has not been established. See the
[reconnect investigation](../troubleshooting/muted-path-wedge.md).

The receiver/native crypto, socket lifetime and ESP-NOW resource investigation
remains open. Phase 1 requires separately authorized physical measurements and
at least 30 uninterrupted stable minutes plus controls/reconnect checks; Phase 2
BLE HID Disconnect remains blocked on that acceptance. No hardware deployment
or physical acceptance is implied by preparing this release draft.
